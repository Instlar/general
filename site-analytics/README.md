# Мои сайты — общая статистика

Автономный сервис статистики, созданный на основе подхода к посещениям и `session_heartbeat` из админки «Тугарина». **Не использует код и базу игры в процессе работы**. Не зависит от Google Analytics / Яндекс Метрики.

## Что уже готово

- Одна админка для любого количества сайтов: `/admin`.
- Первые два сайта уже в списке: `baking` — «Здоровая выпечка», `plants` — «Комнатные растения».
- Добавление сайтов и редактирование разрешённых доменов прямо из кабинета.
- Посетители, посещения, просмотры, среднее/медианное время на сайте; посещения по дням, популярные URL, источники переходов.
- Периоды: сегодня, 7, 30 и 90 дней.
- Миниатюрный счётчик для сайтов: браузер сам отправляет посещение и время видимости активной вкладки. Скрытая вкладка не учитывается. Это **оценка времени просмотра**, а не доказательство, что человек всё время читал.
- Без внешних сервисов, без хранения IP, имён, почты и User-Agent. У посетителя сохраняется случайный анонимный ID в localStorage конкретного сайта, позволяющий считать уникальные посещения и повторные визиты. Это надо описать в политике конфиденциальности каждого сайта.
- Однофайловая SQLite-база; хранится отдельно от «Тугарина».

## Требования

Node.js **22.13+** (лучше Node.js 24 LTS). В Node.js 22 модуль `node:sqlite` может выдавать предупреждение об экспериментальном статусе. NPM-зависимостей нет.

## Запуск

1. Скопировать проект в отдельный каталог на сервере, НЕ внутрь каталога игры.
2. Создать `.env` из `.env.example`, задать **длинный** `ADMIN_PASSWORD` и **случайный** `SESSION_SECRET` (не менее 32 символов). Не публиковать их в GitHub.
3. Запустить из директории проекта:

   ```bash
   node --env-file=.env server.mjs
   ```

   Или передать переменные окружения через панель хостинга и запустить `npm start`.
4. Подключить отдельный HTTPS-домен статистики (например, `stats.example.ru`) к `http://127.0.0.1:4301` через reverse proxy, включить `TRUST_PROXY_HTTPS=1`.
5. Открыть `https://stats.example.ru/admin` и войти с `ADMIN_PASSWORD`.
6. Нажать «Настроить сайт» у «Здоровой выпечки», указать её точный HTTPS-домен. Указать оба варианта с `www` и без него, если оба используются. Для тестирования можно добавить `http://localhost:3000`.
7. Скопировать готовый код подключения из окна настроек и вставить перед `</body>` на каждую страницу сайта (для обычного статического HTML). Если страницы создаются общим шаблоном, достаточно вставить в этот шаблон.

Пример после выбора домена статистики:

```html
<script defer src="https://stats.example.ru/tracker.js" data-site="baking"></script>
```

Скрипт работает независимо от сайта «Комнатные растения»: у него будет `data-site="plants"`.

### Не учитывать свои тестовые посещения

Открой **свой публичный сайт** с параметром `?__analytics=off` (один раз на каждом браузере и домене). Счётчик отключится на этом устройстве. Чтобы вернуть: `?__analytics=on`. Не распространяй такие URL среди посетителей. Можно также временно не включать счётчик, пока тестируешь сайт.

### Безопасность и размещение

- API приёма статистики разрешает события только с доменов, внесённых тобой в админке. Посетитель не может получать отчёты или менять список сайтов.
- Пароль и секрет сессий хранятся **только** в окружении сервера. Вход защищён HttpOnly/SameSite cookie; для публичного размещения обязателен HTTPS. Есть ограничение неудачных попыток входа.
- Конфигурация сайта не является секретом: любой посетитель видит публичный код счётчика. Как у обычной веб-аналитики, автоматические накрутки полностью не исключаются. При росте трафика можно добавить фильтрацию ботов и лимиты запросов.
- Базу `data/analytics.sqlite` надо включить в резервное копирование.
- На всякий случай **не публикуй сам сервис на GitHub Pages**: серверу нужен Node.js. Код в GitHub — это исходники, а не уже запущенная админка.

## Что не входит в первую версию

Поисковые показы и позиции Google/Яндекса нельзя узнать из собственных посещений сайта: для них нужны данные поисковых систем. Игра не нужна для работы этого сервиса. Новые сайты можно добавлять из админки без изменений сервера.

## Тесты

`npm test` — проверяет вход, изоляцию сайтов, разрешённые домены, счётчик событий, длительность, защиту отчётов и отсутствие дублей.
